# Agent Note: One center-column panel-mount core for ssh and task-board

Status: implemented

## Problem

dsh-ssh `src/client/mount.tsx` and dsh-task-board `src/client/board-mount.tsx` each carried the full center-column takeover lifecycle — container injection into the single-occupant conversation column, sibling eviction, remount resilience, sidebar click-out — and the two copies were ~100 of ~130 lines identical modulo seven parameters (panel tree, view dataset key, semantic plugin name, CSS class, the two html active attributes, event detail names, controller open/close). The duplication was not hypothetical cost: the same behavioral fixes landed twice, as separate issues and commits — the rc.6 centerCol fallback as #243 (ssh, 61153871f) and #107 (task-board, 2ea4f965a), mutual exclusion and sidebar click-out as c0a98c715 (both files), the SDK locale routing as 170b3df31 (both), and the L2 semantic attributes as d73bffc2a (both). The sidebar-entry pair had already moved its shared logic into `shared/client/sidebar-entry-core.ts` (synced copy); the mount pair never got the same treatment.

## Decision

The takeover lifecycle now lives exactly once in `shared/client/panel-mount-core.ts`: `mountCenterPanel(options)` owns the column selector, the MutationObserver remount, the eviction-and-activate sequence, the sidebar click-out listener, and the disposer order; the `CenterPanelMountOptions` contract carries the per-plugin parameters (panel tree, view dataset key, semantic plugin name, CSS class, the plugin's own html active attribute, the panel name) plus the controller subscribe and the optional locale source. The file joins the sync-shared manifest with two generated copies (`packages/dsh-ssh/src/client/panel-mount-core.ts` and `packages/dsh-skill-explorer/src/client/panel-mount-core.ts`); the sync-shared test's copy-count buckets are 105 total and 45 client. Each wrapper stays the parameter wiring and keeps its public exports (`mountPanel` + `PANEL_VIEW_SELECTOR`). The rebuilt aggregate client bundle (`packages/dsh-web-all/lib/client.js`) ships the same behavior inlined from source.

Occupancy across panels moved from per-panel sibling parameters to the shared `PANEL_FAMILY` table when the skill center became a third center-column panel: see [One center-column panel family](../../architecture/2026-09-23-center-column-panel-family.md). The pairwise sibling options this note describes no longer exist.

Container attribute names stay wrapper-supplied parameters: they are pinned by each package's CSS (`panel.module.css` cross-references the family's html attributes), the wallpaper-exclusive skin patches, and the semantic-attributes contract, so the extraction deliberately changes none of them.

## Later change: task-board left the takeover for the native layout seats

The task board no longer consumes this core. It contributes a `sidebar.panellist` row and a keyed `main` page through the official slots system and drives `ctx.layout.selectPanel`, so the shell owns the center column and the board renders in the same container the desktop application's Plugins page uses; the DOM takeover, its self-healing observer, the `html[data-dsh-taskboard-active]` visibility contract, and its `panel-mount-core.ts` copy are gone from the package. See [task-board native panel adoption](../../architecture/2026-09-25-task-board-native-panel-and-timer.md).

Cross-plugin exclusivity did **not** go with it. dsh-ssh and the skill center still take the column over at the DOM level, and while either one's `<html>` attribute is set its stylesheet hides every other column child — the board's page included. Neither is a layout panel, so the layout cannot deselect the board for them; the board therefore keeps participating in the shared `dsh-panel-activate` protocol (`PANEL_ACTIVATE_EVENT`, details `taskboard` / `ssh` / `skill-explorer`) defined here, in `packages/dsh-task-board/src/client/native-panel.tsx`: opening the board announces `taskboard` so a takeover panel releases the column, and an incoming takeover announcement closes the board. `coordinateWithFamilyPanels` names the takeover rows in `TAKEOVER_PANEL_NAMES` because the board cannot value-import this file (browser bundles must stay self-contained), so adding a DOM-takeover family panel means adding its name there as well as its `PANEL_FAMILY` row. This is the one behavior this core still shares with the board, and it is the reason the event name and detail values remain a contract rather than a private detail of the ssh copy.

## Testing

The core's lifecycle spec is `packages/dsh-ssh/tests/center-panel-lifecycle.test.tsx`: it mounts all three `PANEL_FAMILY` rows and asserts eviction, remount resilience, locale re-render, and disposer ordering. The task board's own suites cover the seats it moved to instead: `native-panel-registry.spec.ts` (row and page registration), `panel-coexistence.spec.ts` (the `dsh-panel-activate` handshake with both DOM-takeover panels), and `board-view.spec.tsx` (the board page and its L2 semantic attributes). Repository gates for this change: `pnpm typecheck`, `pnpm test`, `pnpm test:standards`, `pnpm docs:check`, `pnpm i18n:check`, `node scripts/sync-shared.mjs --check`, and `node scripts/aggregate.mjs --check`.

## Alternatives considered

- Leave the duplication and rely on review to keep the copies in sync: rejected — the four-tandem-fix history above shows review does not catch it; the next fix lands twice or the copies drift.
- Extract a runtime npm package imported by both plugins: rejected — client bundles must stay self-contained per the browser bundle purity rules; the sync-shared committed-copy pattern is the repo's established mechanism (same as the settings trio and sidebar-entry-core).
- Parameterize only the attribute names but keep two `ensure`/observer implementations: rejected — the remount and eviction logic is exactly the part that needed the paired fixes; a half-extraction keeps the risky half duplicated.

## Consequences

A future behavioral fix to the takeover lifecycle lands once in `shared/client/panel-mount-core.ts` plus a `node scripts/sync-shared.mjs` run. A third panel adopting the takeover pattern adds a generated copy and a wrapper instead of copying 100 lines — the skill center did exactly that when it left the overlay-modal form ([One center-column panel family](../../architecture/2026-09-23-center-column-panel-family.md)). Raw committed line count rises slightly (one shared source plus generated copies) — the accepted sync-shared trade: single editable source, self-contained packages. Behavior, CSS selectors, html attributes, event names, and the semantic-attributes contract are unchanged; [the remount-resilience fix](../../bug-fix/2026-08-27-task-board-return-button-and-remount-resilience.md) is now carried by the one core. The board's exit from the core added one manual coupling to keep in step: a DOM-takeover family panel must be named in both the `PANEL_FAMILY` table here and `TAKEOVER_PANEL_NAMES` in the board's `native-panel.tsx`; its coexistence spec fails if the handshake breaks.
